{% comment %} The comment column on the edit pages, for a tossup or a bonus. Context: question, qtype ('tossup'/'bonus'), thread_data (from {% get_threaded_comments %} in the caller, which also needs the count to decide whether to give the column any width), plus qset / role / request. Both edit pages carried a copy of this markup, which is how they drifted; one partial means one design for both. Everything is inside .comments because that is what the page re-fetches and swaps in after a comment is posted, edited or resolved (qemsRefreshComments) -- including the heading, so its count is right without anyone updating it. The class names the scripts hang off are load-bearing: .comment-item with data-comment-id, .comment-quote, .comment-strikeable with data-raw, .comment-actions as a direct child of .comment-item (the in-place editor inserts itself after it), .reply-form#reply-form-, .add-comment-form. {% endcomment %} {% load filters %} {% load comments %}
