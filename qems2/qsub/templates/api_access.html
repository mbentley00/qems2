Adding the Discord bot to your playtest server

The playtest bot (“Cliff”) reads the T | / B | question threads on a Discord server and posts the feedback, buzz points and bonus results to this set. Linking a server takes three steps.

  1. Invite the bot to the server. You need Manage Server on the Discord server to do this. Open the bot's invite link (ask whoever runs the bot for it, or build one in the Discord Developer Portal under OAuth2 → URL Generator with the bot scope) and pick your server. Grant it these permissions — it needs nothing else:
    • View Channels — to find the playtest channels and their threads
    • Read Message History — to read feedback, reactions and the Results posts already in those threads
    • Send Messages and Send Messages in Threads — to reply when you @mention it
    Together these are the permissions integer 274877975552. If you build the invite link yourself, the URL is https://discord.com/oauth2/authorize?client_id=<application id>&scope=bot&permissions=274877975552.
  2. Make sure it can see the playtest channels. A server-level permission is overridden by private channels or categories. If your playtest channels are restricted to a role, add the bot (or its role) to those channels with View Channel and Read Message History. Threads inherit from their channel, so that is enough.
  3. Link the server to this set. Generate the key above, then DM the bot add. It asks for the server ID (Discord → Server Settings → Widget, or right-click the server with Developer Mode on and Copy Server ID) and then for this key, and checks the key against QEMS before saving. test confirms the connection; autosync live makes it sync on its own a few minutes after playtesting goes quiet, or @mention it in any channel to sync right away. help lists everything it understands.

If you host your own copy of the bot (the discord_qems project) rather than using the shared one, also enable the Message Content and Server Members privileged gateway intents on your application's Bot page in the Developer Portal — without them the bot connects but sees no message text and cannot resolve who buzzed.

How the bot uses the key

Send the key on every request as a Bearer token. Questions are matched by their answer line (no QEMS IDs needed); if a question doesn't exist in the set yet, the item comes back unmatched and the bot should retry it later. Include a unique external_id per item so retries don't record duplicates. 

Base URL: {{ base_url }}
Header:   Authorization: Bearer <your key>

# Validate the key
GET  {{ base_url }}/api/v1/ping

# Record tossup buzzes (who buzzed + optional wrong answer)
POST {{ base_url }}/api/v1/buzzes
{
  "events": [{
    "external_id": "game42-pkt3-q5-user99",
    "answer": "Blaise Pascal",
    "player_name": "someuser#1234",
    "buzz_word_index": 12, "total_words": 45,
    "correct": false, "powered": false, "neg": true,
    "answer_given": "Fermat"
  }]
}

# Record bonus results
POST {{ base_url }}/api/v1/bonus_results
{
  "events": [{
    "external_id": "game42-pkt3-b5-user99",
    "answer": "Bastille",
    "player_name": "someuser#1234",
    "part1_correct": true, "part2_correct": false, "part3_correct": false
  }]
}

# Add comments to a question
POST {{ base_url }}/api/v1/comments
{
  "comments": [{
    "external_id": "game42-pkt3-q5-cmt1",
    "answer": "Blaise Pascal",
    "author_name": "someuser#1234",
    "qtype": "tossup",
    "text": "Second clue might be too easy."
  }]
}
